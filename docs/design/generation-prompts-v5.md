# Theological research and routing: version 5 prompts

Historical prompt archive. The current scope is a personal-use neutral theological research tool with practical quality checks and authentic, traceable online sources. The original prompts are preserved as image provenance; [functional.md](../../functional.md) takes precedence over any older institutional-only, project-evaluation or release-gate wording in them. A provisional role fit can be used without a prior expert benchmark; the existing pin rule remains in force.

Tool: built-in `image_gen`, opaque background. The existing `compass-research-v4.png` was used as a visual-identity reference for each independently generated screenshot. These are concepts, not captures of a running application. Files were copied into this workspace and visually inspected.

| Output | Purpose |
| --- | --- |
| `compass-theology-research-v5.png` | Proposed readings, evidence types, context and open questions |
| `compass-theology-roundtable-v5.png` | AI discussion under human moderation with shared evidence |
| `compass-orchestrator-routing-v5.png` | Illustrative role allocation constrained to enabled model connections |

The example topic is *Faith and good deeds*. The passages are illustrative research leads, not a completed evidence review. Proposed readings and generic support/counterevidence descriptions are not attributed scholarly findings. The generated image is not evidence that a suggested passage supports a conclusion. No sacred text or manuscript image was generated as a historical source.

The routing screen explicitly uses demo connections and provisional assignments. Those do not establish real account access, current connection status or superior model fit. It does not show keys or real API usage. Provider glyphs are illustrative, not verified corporate logo assets. The interpretation and discussion screenshots show web research disabled; the routing reference image generated the web control as enabled. These are separate illustrative screen states, not an implied live state transition. In implementation, connection settings remain shared and persistent according to the product contract. No cloud credentials were configured or model API tests run for these images.

Visual inspection covered English labels, blue/gold treatment, equal collection styling, proposed-reading uncertainty, distinct evidence types, moderator controls and illustrative model assignment. Keyboard interaction, panel resizing, text accuracy, contrast, RTL and actual model/tool behavior still require implementation and live testing.
